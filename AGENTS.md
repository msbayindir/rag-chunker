# AGENTS.md

Guidance for AI coding agents (Codex, Claude Code, Cursor, Copilot, Gemini CLI…) and for the people
who use them on this repository. Humans: see also [CONTRIBUTING.md](CONTRIBUTING.md).

## What this is

`@msbayindir/rag-chunker` turns PDFs, scans, Office files, HTML and images into cited,
retrieval-ready chunks. Node.js ≥ 22, TypeScript, ESM, published to npm and run with `npx`. It works
with no API keys (PDF text layer + local ONNX models) and can use cloud models per stage. There is
no Python anywhere in the package, and that is a design rule, not an accident.

## Commands

| Command | Use |
| --- | --- |
| `npm install` | Setup |
| `npm run check` | Lint (Biome) + typecheck + unit tests. Run before every commit |
| `npm run format` | Apply Biome formatting (single quotes, no semicolons, 110 columns) |
| `npm test` | Unit, property and mock-server tests: no network, no keys |
| `npm run build` | Compile to `dist/` and regenerate `schema/config.schema.json` |
| `npm run test:pack` | Pack, install in a temp folder, run the CLI and the API |
| `npm run test:live` | Real model calls (Ollama, keys from `.env`); opt-in, never in CI |
| `npm run bench` | The internal 5-document benchmark (rewrites `bench/README.md`) |

## Where things are

```

  chunker/     AST chunker, splitting, tokenizer, chunk ids
  documents/   input detection; PDF text layer, rendering, layout lines, tables, figures; DOCX, PPTX, XLSX, HTML
  local/       local ONNX models: catalogue (models.ts), runtime/devices, layout, OCR, tables, formulas, reranker

  config/      zod schema (single source of truth), loading, presets, provider definitions
  structure/   heading repair          context/   contextual retrieval
  embeddings/  batching, caching       cache/     content-addressed cache
  output/      files, manifest, quality report
  search/ eval/ export/ mcp/ cli/
test/unit/     tests per area; fixtures are generated by test/fixtures/generate.ts
scripts/       benchmark runners, schema generation, Hugging Face model mirror, pack smoke test
bench/         internal benchmark corpus card, questions and results; external results in bench/results/external
```

## Rules

1. **The chunker never loses text.** Every input word appears in the output, text chunks respect
   `maxTokens`, table parts repeat their header row, page ranges are valid and `chunkId`s are stable.
   The property tests in `test/unit/chunker.test.ts` guard this; they must stay green.
2. **No Python, light install.** Models run on `onnxruntime-node`. Heavy or native packages are
   `optionalDependencies` loaded with `importOptional` (`src/util/optional.ts`), so `npx` works without
   them and the error tells the user what to install.
3. **Local models go through the catalogue.** Every model file is an entry in `src/local/models.ts`
   with its URL on the project's Hugging Face mirror, sha256, size and licence. Files are downloaded
   on first use and verified; they are never committed or bundled in the npm package. Mirroring is a
   maintainer step (`npm run hf:mirror`).
4. **Keys only from the environment.** Never in config files, code, logs, cache keys, fixtures or
   commits. `.env` is gitignored. Tests use the mock server in `test/helpers/`.
5. **Measure before changing a default.** A change that can move quality (OCR, layout, tables,
   formulas, chunking, search, a default model) comes with before/after numbers from `npm run bench`
   and, where relevant, the external runners (`bench:omnidocbench`, `bench:financebench`,
   `bench:squad-tr`). Put the numbers in the PR. `npm run bench` rewrites `bench/README.md`; restore it
   with `git checkout -- bench/README.md` unless you mean to update the published results.
6. **No benchmark data in the repository.** OmniDocBench, FinanceBench and SQuAD-TR have research or
   non-commercial licences: commit scores only, never their pages, annotations or questions.
7. **Cache keys carry everything that changes the result.** Add the setting or model to the key, and
   raise the store's version when the cached shape changes. A cached result must never hide a changed
   setting.
8. **Configuration has one source.** Options live in the zod schema in `src/config/schema.ts` with a
   `.describe()` text. After changing it, run `npm run build` (regenerates the JSON schema) and add the
   option to the configuration tables of both `README.md` and `README.tr.md`.
9. **Errors tell the user what to do.** User-facing errors are `RagChunkerError` with a `code` and a
   `hint`.

## Style

- TypeScript `strict` with `noUncheckedIndexedAccess`; no `any`. ESM with `NodeNext` resolution.
- Small, focused modules; comments explain why, not what.
- Every behaviour change gets a unit test; a bug fix gets a test that fails without the fix.
- Docs: `README.md` (English) and `README.tr.md` (Turkish) stay in sync; user-visible changes get a line
  under `## Unreleased` in `CHANGELOG.md`.
- Conventional commit messages (`feat:`, `fix:`, `docs:`…).

## Where to start

Open problems with numbers and pointers are filed as issues labelled
[`help wanted`](https://github.com/msbayindir/rag-chunker/labels/help%20wanted) and
[`good first issue`](https://github.com/msbayindir/rag-chunker/labels/good%20first%20issue).

## Before you open a PR

- `npm run check` passes; `npm run build` if the schema or the CLI changed; `npm run test:pack` if
  packaging or entry points changed.
- Numbers attached if a default or the extraction quality could change (rule 5).
- No `dist/`, model files, `.env`, benchmark data or generated fixtures in the diff.
- Do not raise the version or publish; releases are done by the maintainer.
